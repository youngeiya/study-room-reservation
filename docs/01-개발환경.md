# 개발 환경

자습실 예약 시스템을 개발·실행·테스트하는 데 쓴 환경과 방법을 정리한 문서입니다.
서비스 규칙과 설계 이유는 [README](../README.md), 구조는 [시스템 아키텍처](02-시스템-아키텍처.md), 데이터는 [데이터 모델](03-데이터-모델.md)을 봅니다.

## 1. 한눈에 보기

| 구분 | 내용 |
| --- | --- |
| 개발 PC | Windows 11, VS Code, PowerShell / Git Bash |
| 런타임 | Node.js v26 (개발 PC), 컨테이너는 `node:22-alpine` · npm 11 |
| 백엔드 | NestJS 12 + TypeScript 6 |
| 프론트엔드 | Vue 3.5 + Vite 8 + TypeScript 6 + Vuetify 3 |
| 데이터베이스 | Oracle 26ai Free (서비스 `FREEPDB1`, 문자셋 AL32UTF8) / 설치 없이 쓰는 JSON 파일 DB |
| 파일 저장소 | SeaweedFS (자습실 사진) |
| 배포 | Docker Compose (nginx · backend · seaweedfs), Linux 서버 |
| 형상 관리 | Git, GitHub (`main` 브랜치) |

> 프론트엔드는 Node `^22.18.0 || >=24.12.0`을 요구합니다 (`frontend/package.json`의 `engines`).

## 4. 실행 방법

### 4-1. 로컬 — JSON 파일 DB (가장 간단)

Oracle·SeaweedFS 없이 바로 실행됩니다. 자습실 사진 기능만 SeaweedFS가 필요합니다.

```bash
# 터미널 1: 백엔드
cd backend
npm install
npm run start:dev        # http://localhost:3000

# 터미널 2: 프론트엔드
cd frontend
npm install
npm run dev              # http://localhost:5173
```

데이터는 `backend/data/db.json`에 저장되고, 처음 실행하면 예시 학생 5명·자습실 3개·강사 계정이 자동으로 만들어집니다.

### 4-2. 로컬 — Oracle + SeaweedFS

```bash
# 1) SeaweedFS (PowerShell. Git Bash 에서는 /data 가 Windows 경로로 바뀌어 실패한다)
docker run -d --name seaweed --restart unless-stopped -p 8888:8888 chrislusf/seaweedfs server -filer -dir=/data

# 2) Oracle 스키마 (STUDYROOM 계정으로 db/oracle 의 SQL 을 순서대로)
#    01_create_user → 02_schema → 03_seed   (이미 만든 DB 는 마이그레이션 05~08 을 필요한 것만)

# 3) backend/.env  (backend/.env.example 을 복사해서 채운다)
DB_TYPE=oracle
ORACLE_USER=studyroom
ORACLE_PASSWORD=...
ORACLE_CONNECT_STRING=호스트:1521/FREEPDB1
JWT_SECRET=16자_이상의_무작위_문자열
```

이후 4-1과 같이 백엔드·프론트엔드를 실행합니다.

### 4-3. Docker Compose (서버 배포와 같은 방식)

```bash
docker compose up -d --build        # http://localhost:8080
WEB_PORT=18900 docker compose up -d --build   # 포트 변경
```

Oracle을 쓰려면 같은 명령 앞에 `DB_TYPE=oracle ORACLE_USER=... ORACLE_PASSWORD=... ORACLE_CONNECT_STRING=... JWT_SECRET=...`을 지정합니다(서버에서는 `.env`에 적어 둡니다).
컨테이너는 `restart: unless-stopped`라서 서버를 재부팅해도 다시 뜹니다 (`sudo systemctl enable docker` 필요).

## 5. 환경 변수

`backend/.env.example`을 `backend/.env`로 복사해 사용합니다 (`.env`는 Git에 올리지 않습니다).

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DB_TYPE` | `json` | 저장소 종류: `json` / `oracle` |
| `DB_FILE` | `./data/db.json` | JSON DB 파일 위치 |
| `ORACLE_USER` · `ORACLE_PASSWORD` · `ORACLE_CONNECT_STRING` | — | Oracle 접속 정보 (`호스트:1521/FREEPDB1`) |
| `JWT_SECRET` | 임시 생성 | 토큰 서명 키(16자 이상). 없으면 서버를 켤 때마다 바뀌어 모두 다시 로그인해야 함 |
| `INSTRUCTOR_ID` · `INSTRUCTOR_PASSWORD` | `admin` / `admin1234` | **처음 만들 때만** 쓰는 강사 계정 |
| `BOOKING_MAX_DAYS_AHEAD` | `3` | 예약 가능 기간(일) |
| `LOGIN_MAX_ATTEMPTS` · `LOGIN_LOCK_MINUTES` | `5` · `5` | 로그인 연속 실패 허용 횟수 · 잠금 시간(분) |
| `SEAWEEDFS_FILER_URL` | `http://localhost:8888` | 사진 저장소 주소 (Docker 구성에서는 `http://seaweedfs:8888`) |
| `PORT` | `3000` | 백엔드 포트 |

## 7. 테스트

| 종류 | 범위 | 수 | 실행 조건 |
| --- | --- | --- | --- |
| 백엔드 단위 | 서비스 규칙(정원·하루 1건·예약 가능 기간·학생·자습실·사진), 동시성, 저장소, 로그인 | 102 | 항상 |
| 백엔드 e2e | 로그인·권한·사진 업로드(HTTP, 메모리 이미지 저장소 사용) | 23 | 항상 |
| Oracle 통합 | 실제 Oracle에서 동시성·제약 검증 | 9 | `ORACLE_TEST_*` 환경 변수가 있을 때만 |
| 프론트엔드 | 날짜 변환 유틸 | 2 | 항상 |

- Oracle 통합 테스트는 시작할 때 대상 스키마의 **모든 데이터를 지웁니다.** 반드시 `02_schema.sql`만 적용한 **테스트 전용 계정**으로 실행하세요.
- 화면은 헤드리스 Chrome으로 직접 시나리오(로그인·역할 분리·예약 기간·잠금)를 확인했지만 자동 테스트로 남기지는 않았습니다.

## 8. 서버 배포 (Linux + Docker)

```bash
git clone https://github.com/youngeiya/study-room-reservation.git
cd study-room-reservation
# .env 에 DB_TYPE, ORACLE_*, JWT_SECRET, WEB_PORT 등을 적는다
docker compose up -d --build
```

- 코드 업데이트: Oracle 마이그레이션이 있으면 **먼저 실행**한 뒤 `git pull && docker compose up -d --build`
- 상태 확인: `docker compose ps`, `docker compose logs backend`
- 사진 파일은 `seaweed-data` 볼륨에, JSON DB를 쓸 때의 데이터는 `db-data` 볼륨에 보관되어 컨테이너를 다시 만들어도 남습니다.
